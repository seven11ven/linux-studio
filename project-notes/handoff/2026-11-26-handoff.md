## 3. dev4: written and tested, NOT committed (finish this first)

### 3.1 Extension signature checker (`src/editor/vsce-sign/index.js`, `package.json`)
- **Problem:** installing any extension said "Signature verification was not executed". Code - OSS lacks Microsoft's closed-source `@vscode/vsce-sign`.
- **Fix:** our own open-source module under that name, using Node built-ins only:
  - parses Open VSX's `.sigzip` (64-byte Ed25519 `.signature.sig` plus `.signature.manifest`)
  - checks the package's size and SHA-256
  - verifies Ed25519 over the raw `.vsix` against the **pinned Open VSX key**: id `14ccb407-4e79-41ed-be5a-6d608325c45a`, DER SHA-256
    `ffd108d00f4dac32e52b358a3452e15fe09815607b9d74d7ea39a3db49d4b623`
- **The key:** verified to be the one every sampled extension references, including versions from 2020. The older 2024 key `e7641871…` no longer exists.
- **PM decisions:**
  - Missing **and** wrong or tampered signatures → refuse, with **Install Anyway**. This is the editor's built-in prompt.
  - The check can be switched off in Settings.
- **Verified in the real editor CLI** (inside a runtime-based test sandbox):
  - a genuine extension → "Success"
  - a wrong key → `SignatureIsNotValid`, nothing installed
  - `extensions.verifySignature: false` → installs without the check
- **Build:** a new step in `.github/workflows/build-editor.yml` copies it to `resources/app/node_modules/@vscode/vsce-sign`. It has also been
  **copied into the local build** `build-cache/editor/1.148.0/app/…` (ignored by git) for dev4.
  **The PM must re-run "Build Linux Studio editor" on `dev`** so the official build includes it, along with the earlier branding and walkthrough.

### 3.3 Remove my Linux Studio data
- **Ways to run it:**
  - Settings > "Your data": a red button opens a confirmation card with tick boxes.
  - `linux-studio --remove-my-data` (interactive; type `remove` to confirm).
  - `--remove-my-data-now PARTS` (used by Settings).
  - `--is-running`.
- **Parts:**
  - `extensions` = `~/.local/share/linux-studio/home` (extensions, editor settings, logins)
  - `toolchains` = `~/.local/share/linux-studio/toolchains`
  - `settings` = `~/.config/linux-studio` (Settings choices, approved websites, project folder choice; unticked by default)

  The **project folder is never touched.**
- **Safety:**
  - Refuses while any Linux Studio runs. The running registry is `~/.local/share/linux-studio/running/<pid>`; a lock-file fd would have leaked the
    host path into the sandbox through `/proc/self/fd`.
  - Deletes only real folders at their exact paths, never links.
  - Uses `rm --one-file-system`.
- **Why uninstall doesn't remove this data:** Debian rules and our guidelines forbid package scripts touching home folders. The PM asked for this button instead.

- **Does uninstalling remove extensions?** No. They live in `~/.local/share/linux-studio/home/.linux-studio/extensions`. Remove them with Remove my data
  (dev4) or `rm -rf ~/.local/share/linux-studio`.
- **Can Unity projects be used?** Partly today (editing only). Proper support is planned as Phase 7.

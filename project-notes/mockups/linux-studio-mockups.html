Linux Studio · Setup

Choose your project folder

Linux Studio can only see this one folder. Inside the app it always appears as project-folder.

You can change this later with linux-studio --set-project-folder.

The folder will be created if it doesn't exist. Linux Studio can't see your home folder, other drives or system files.
project-folder $ mkdir apples && cd apples project-folder/apples $ pwd project-folder/apples

What happens

  • Shown only on the first launch, or when the saved folder is missing.
  • Browse opens your system's normal folder picker. It runs outside the sandbox, before the app starts.
  • The choice is saved in ~/.config/linux-studio/config.

Nothing is waiting.

What happens

  • In the editor (top window): a small 🌐 N waiting item at the right end of the status bar, next to the notification bell. It appears only while something is waiting, and clicking it opens the Network inbox. It shows the count only: the editor runs inside the sandbox, so it can't answer requests. Linux Studio gives it the count through a read-only file, and "open the inbox" requests from it are rate-limited.
  • New (PM choice A): new websites no longer get one pop-up each. A single small notice shows how many are waiting and updates its count in place. It never takes the keyboard.
  • As built (after the security review): the inbox also has Block new sites until restart (emergency stop); Deny all refuses until restart without saving; an inbox opened from the editor's status bar doesn't take the keyboard (click it first).
  • Open inbox lists every waiting site with Deny, Allow once and Always allow, plus Deny all. Buttons unlock after 1 second, like the pop-up.
  • While a site waits, its connections are refused. The extension or tool usually retries and works once you allow it.
  • Requests expire after 10 minutes (PM choice) if you don't answer, and count as denied until something asks again.
  • The inbox is a desktop window outside the sandbox, like Settings, so code inside can't answer it.
  • Also available from Settings > More > Network inbox… and linux-studio --network-inbox.

Where the look doesn't match yet

  1. Desktop windows are always dark. The editor follows your light/dark setting, but the first-run, pop-up, websites, toolchains and settings windows stay dark. Fix: give them the mockups' light palette too, following the same setting.
  2. Editor icon is still VS Code's. The small icon at the top-left of the editor is the Code - OSS logo. Fix: use the Linux Studio icon (placeholder now; final design before release).
  3. Empty right-hand panel. A blank side panel (VS Code's AI chat area, unused because AI is off) takes space. Fix: hide it by default.
  4. Welcome page mentions VS Code. "Editing evolved" and "Get started with VS Code" are VS Code's text. Fix: turn off VS Code's walkthroughs and use a short Linux Studio welcome.
  5. Light terminal hint text is hard to read. The terminal stays dark in light mode, as in the mockups, but the grey tip text is too faint. Fix: set the terminal's hint and ghost-text colours in the light theme.

Linux Studio · Remove your data
Can't be undone
Are you sure you want to remove your Linux Studio data? Close Linux Studio first. Choose what to delete from this computer. Your project folder is never touched. It stays at ~/LinuxStudio/project-folder.

Saved outside the sandbox, so nothing inside Linux Studio can change these settings. Clipboard changes apply immediately; the signature setting applies the next time Linux Studio starts.

What happens

  • New: Extension signatures. Check signatures (default): every extension downloaded from Open VSX is checked against Open VSX's signature before it installs. A missing, wrong or tampered signature stops the install and shows the editor's prompt, the same kind of box you saw, with Install Anyway to override.
  • Don't check: extensions install without the check, with the warning shown.
  • New: CPU and memory. CPU cores: all but one by default (All, or down to 1, can be chosen); programs inside see only those cores. Memory limit: 75% of your computer's memory by default (No limit, or lower caps, can be chosen). If Linux Studio needs more than the cap, Linux stops the biggest program inside Linux Studio (often a build or an extension) instead of slowing your whole computer; the note turns into a warning when a limit is chosen. Choices are built from your real core count and memory. Applies at the next start. If your system can't enforce a memory limit, Linux Studio starts without it and says so.
  • New: Largest extension to check (256 MB, 512 MB default, 1 GB, 1.5 GB). The whole download has to be held in memory to check its signature, so this cap stops an oversized download from exhausting memory. Bigger extensions are refused with Install Anyway. Hidden while Don't check is chosen. Applies at the next start.
  • New: Remove my Linux Studio data. The confirmation is its own pop-up window in front of Settings (Settings can't be used until you answer). Cancel is the default; Remove selected is red and unlocks after 1 second. Uninstalling never deletes your data, so this is how you clear it yourself. It refuses while Linux Studio is open, lets you pick what goes, and never touches your project folder. The same is available as linux-studio --remove-my-data, which asks you to type remove to confirm.
  • Opened from the menu entry “Settings” or linux-studio --settings. A desktop window, outside the sandbox.
  • Paste only (default): your clipboard reaches Linux Studio only at the moment you really paste in its window. Nothing inside can read it in the background, and copies made inside stay inside.
  • Both directions: works like a normal app, with the warning shown.
  • Text only in both modes; no files or images.
Linux Studio · Toolchains
Connected to official download sites only. The connection closes when you close this window.

What happens

  • Every download is checked against the publisher's checksum or signature before it's installed. If a check fails, the file is deleted.
  • Toolchains are stored in ~/.local/share/linux-studio/toolchains. Inside the editor they're read-only.
  • Restart the editor to pick up new toolchains.

about:blank

The page opens in the editor's own browser tab (the dev5 behaviour). No uBlock in this tab.

What happens

  • Firefox ESR (PM choice), installed from Debian's signature-checked archive inside Linux Studio's private runtime. Locked policies turn off telemetry, studies, Pocket, Firefox accounts, feedback, update checks and the default-browser question.
  • Same sandbox as the editor. The browser sees only Linux Studio's network proxy, so every new site goes through the Network inbox, and it uses the same fake identity. Sign-ins to localhost (for example an extension's login) work.
  • Its own window. On X11 it gets its own private display, titled Linux Studio · Private browser, separate from the editor's.
  • Open web links in (PM choice): Private browser by default; Linux Studio tab keeps today's in-editor tab. Covers editor links, xdg-open in the terminal and extension sign-in pages.
  • Logins and history (PM choice: a Settings choice). Forget when closed by default: nothing is kept between sessions. Remember keeps them in Linux Studio's private data, never in your own Firefox profile.
  • uBlock Origin (PM choice) from Debian, always on, with its default filter lists. Its list updates also go through the Network inbox.
  • linux-studio:// sign-in callbacks from the browser are sent back to the editor through the same checked link router as today.
  • Remove my data gains a tick box: Private browser logins and history.
  • Also available as linux-studio --private-browser (name to confirm).
